# FitBridge MVP 产品需求文档

**版本**：0.1（作品集概念原型）  
**产品形态**：微信小程序概念验证；当前交付是可浏览器运行的交互 Demo  
**首发区域**：墨尔本  
**目标用户**：中国留学生健身新手  
**状态**：待真实用户与健身房试点验证

## 1. 产品目标

帮助新会员在场馆内更快找到器械并理解基础信息，减少在通用视频与现场询问之间来回切换的需要。对健身房的商业价值暂定为改善新会员入门体验；是否能减少员工重复解释或改善留存尚未验证。

## 2. 目标与非目标

### MVP 目标

- 用户无需登录即可浏览所选场馆的示例器械目录。
- 通过搜索或分类找到器械。
- 在详情中看到中英名称、场馆位置、简明说明、步骤、注意提示和预设替代项。
- 支持收藏状态，便于用户回看。
- 原型能展示关键路径与产品边界，支持后续可用性访谈。

### 非目标

- 证明真实市场需求、健身房付费或会员留存提升。
- 实时器械空闲状态、排队、预约或器械联网。
- 自动生成训练处方、负重建议或医疗建议。
- 用户账户、会员数据同步、支付、健身房后台和生产级分析。
- 当前交付不是真正部署到微信的小程序。

## 3. 用户故事

1. 作为第一次到新健身房的留学生，我想看懂器械中英文名称，以便匹配现场标签。
2. 作为不熟悉场馆的会员，我想知道器械所在区域，以便少走弯路。
3. 作为不知道怎么开始的用户，我想读到简短的入门步骤和注意事项，以便理解接下来该做什么。
4. 作为器械暂时被使用的用户，我想查看预先整理的同类替代项，以便不中断探索。
5. 作为回访用户，我想收藏常用器械，以便快速找到它们。
6. 作为健身房负责人，我想看到场馆内容如何呈现、需要谁维护，以便评估试点成本。

## 4. MVP 功能清单

| 优先级 | 功能 | 需求描述 | 验收要点 |
|---|---|---|---|
| P0 | 场馆上下文 | 首页显示当前演示场馆，可切换场馆 | 切换后显示所选场馆名称与对应目录 |
| P0 | 器械列表 | 展示器械卡片、中英文名称、简短信息与区域 | 卡片清晰可点开详情 |
| P0 | 搜索 | 支持中英文关键词过滤 | 无匹配时展示明确空状态 |
| P0 | 分类筛选 | 按身体部位/器械类别筛选 | 可选全部并恢复完整列表 |
| P0 | 器械详情 | 显示中英名称、位置、说明、步骤、提示 | 返回列表后保留基本浏览上下文 |
| P0 | 替代项 | 展示器械被占用时的预先整理备选 | 明示不是实时占用数据 |
| P1 | 收藏 | 收藏/取消收藏单项器械 | 页面状态即时反馈；本 Demo 仅运行时保存 |
| P1 | 底部导航 | 首页、收藏、我的的视觉入口 | 可切换原型状态；非完整账户能力 |
| P2 | 场馆扫码入口 | QR 到场馆/器械详情 | 后续接入真实小程序路由时再实现 |
| P2 | 事件分析 | 搜索、详情打开、替代项点击、复访 | 先定义指标，再评估隐私与合规要求 |

## 5. 用户流程

```text
健身房欢迎消息 / 前台二维码
          ↓
      FitBridge 首页
          ↓
确认或切换当前场馆
          ↓
搜索器械 / 选择分类
          ↓
打开器械详情
   ├─ 查看中英名称与所在区域
   ├─ 阅读简短步骤与注意事项
   ├─ 收藏器械
   └─ 器械忙碌 → 查看预设替代项 → 打开替代器械
```

此版本不需要登录；扫描二维码和场馆识别在界面中仅以演示交互表达。

## 6. 页面规划

| 页面/状态 | 主要内容 | 关键交互 |
|---|---|---|
| 首页/器械目录 | 品牌与场馆、欢迎提示、搜索、分类、器械卡片 | 搜索、筛选、切场馆、打开详情 |
| 器械详情抽屉 | 双语名称、区域、简短入门信息、步骤、注意提示 | 收藏、打开替代项、关闭 |
| 收藏状态 | 收藏数量与已收藏器械 | 进入已收藏详情、取消收藏 |
| 空搜索状态 | 无结果提示及清除筛选操作 | 回到全部器械 |
| 我的/说明状态 | Demo 边界、内容安全与场馆信息说明 | 返回首页 |

## 7. 内容与数据模型（概念）

```text
Gym(id, name, suburb, updatedAt)
Equipment(id, gymId, nameZh, nameEn, category, zone, summary, steps[], caution, alternatives[])
Alternative(equipmentId, reason, relationLabel)
UserPreference(favoriteEquipmentIds[])
```

所有演示内容均为静态样例。正式内容需要来源、审核人、更新时间、场馆确认和下架机制；替代动作需专业审核。

## 8. 体验与质量要求

- 手机优先布局，支持常见窄屏和桌面预览。
- 信息先给名称、位置和用途，再给步骤和注意信息。
- 操作控件有明确触达区域、状态反馈和可读对比度。
- 中文作为主语言，英文名称作为识别辅助。
- 加载、无结果和无收藏等状态均给出清楚反馈。
- Demo 不收集或发送个人数据；不模拟真实微信登录。

## 9. 指标与实验

### 体验指标（试点前定义）

- 任务完成率：用户能否在限定任务中找到指定器械。
- 首次找到时间：从首页到打开正确详情的时长。
- 内容理解率：用户能否复述器械位置与页面说明的关键含义。
- 替代项点击率与后续详情打开率。
- 次周/次月重复访问，仅在有适当同意与隐私设计后测量。

### 商业验证指标

- 具采购权决策者的演示到付费试点转化率。
- 每家场馆的内容采集、审核、更新和支持成本。
- 试点续费/续约意愿及实际续约。

课程报告的试验假设包括：合格会员月活达到 30%、演示后成交率达到 35%。它们是待检验阈值，不是已达成指标，也不等于产品成功结论。

## 10. 验证计划

1. 原型可用性走查：5 位目标新手完成“找史密斯机并查看替代项”等任务。
2. 内容审阅：由具备资质的健身专业人士审核真实器械说明与替代项。
3. 场馆试点：与 1–2 家愿意合作且有授权决策人的场馆确认部署、内容责任和衡量方式。
4. 商业试验：分别讨论固定月费和按使用量等方案，要求采购方给出明确下一步或付费承诺。
5. 复盘门槛：若使用弱、内容维护成本高或没有付费信号，先调整价值主张/服务交付，再扩展开发。

## 11. 依赖与风险

- 场馆提供准确器械清单和位置，并及时告知变化。
- 动作指导由合格专业人员审核，不由 Demo 文案直接视作正式运动建议。
- 微信小程序审核、平台规则、隐私和数据处理要求需在技术立项前确认。
- 需要确认品牌名称、图片/图标素材许可及内容著作权归属。
- 付费意愿、续约、留存效果及竞品差异目前均未验证。
